# Mission 9 Reflection

Automation is important when managing hundreds of cloud servers because doing every task manually takes too much time and can lead to mistakes. Cloud engineers can use scripts to perform repeated tasks such as backing up files, checking systems, and maintaining servers. Automation also helps make operations more consistent because the same commands can run whenever they are needed.

However, automation also has risks. A script with a destructive command or an incorrect file path can delete important data. If that script runs on many servers, the damage can affect multiple systems at once. This is why scripts should be reviewed and tested in a safe environment before being used in production. Backups, access controls, and monitoring are also important.

Writing a Bash script was different from creating a Docker Compose YAML file in Mission 6. Bash uses commands and variables to perform tasks step by step. Docker Compose uses YAML to describe services and their configurations. Both tools reduce manual work, but they solve different problems. Bash is useful for automating commands, while Compose helps manage application services.

Looking back at the cloud computing laboratories, I learned that cloud computing involves more than running applications. It also includes managing infrastructure, deploying services, monitoring performance, securing systems, and automating routine operations. Each activity helped me understand a different part of cloud administration.

Among the roles explored during the semester, I enjoyed the Cloud Automation Engineer role the most because I learned how to use Bash scripts and Cron jobs to automate tasks instead of doing everything manually. I also liked that a simple script could create a backup and help protect important data. This activity showed me that automation can save time and reduce repetitive work. However, automated tasks must still be tested and monitored carefully to protect important data and prevent mistakes from affecting multiple systems.
